The six states, and what renders them
StateUse
DefaultThe component itself. One primary action per view.
LoadingSkeleton when layout is known · Spinner / Button loading for one action · ProgressBar when measurable · TypingIndicator in chat. Region gets aria-busy.
EmptyEmptyState: what belongs here + the one action that fills it. Cory voice on conversational surfaces, neutral on admin.
ErrorField: error prop (Input, Select, Checkbox, Toggle) · Region: Alert danger + Retry · Chat: status="failed" + Retry. Say how to fix it.
PartialAlert warning (stale data, degraded sync) · Input warning · Select emptyMessage · disabled with a visible reason.
SuccessToast after an action (6 s, Undo if reversible) · Alert success when it must stay · Input / Select success.
Rules that keep states kind
1
Explain, don't disableKeep submit enabled and show the field error. Disable only when the reason is visible beside the control.
2
Validate on blur, summarise on submitNever on every keystroke. On submit, focus the first invalid field; its message has role="alert".
3
Nothing silent, nothing blockingEvery wait over 300 ms shows a state; every change is announced (role=status / aria-live). Destructive actions confirm via Dialog tone="danger", never a bare "OK".
4
Never motion or colour aloneSpinners fall back to dots + label under reduced motion; every tone carries a glyph and words.
